The cycle of abandoned projects

I found myself constantly stuck trying to create new projects — and I'd perfected the art of killing them before they lived. Each time a new idea showed up, I'd get lost in the smallest details.

You know when those details mattered? Never. Because I never finished any of the projects. So I wondered: what if I built something completely ridiculous, with no serious value, strictly for fun?

The "stupid" idea: weaponized insults

The idea is simple: a user inputs a password, and the API returns a security score… and an insult. No stakes, no pressure, just a fun little project. roastmypassword.com →

The over-engineering trap

I still wanted to learn something, so since I use Python, JavaScript, and Java daily, I decided to write the API in Rust. No sooner had I started than I caught myself thinking too far ahead:

-"What structure scales easiest in the future?"
-"What if I need a database? What kind of database?"
-…and clever ways to implement the insult generator.

So I made myself remember: none of these thoughts get me closer to finishing. I stopped worrying about what could be needed and wrote only what I needed right now.

Embracing "good enough"

Giving myself permission to be lazy was the hardest part. But once I did, every technical decision became obvious. I didn't need a React SPA with Redux, or a database. I needed a function that took a string and returned a string.

-Language: Rust (to learn it, and insult users blazingly fast)
-Backend: AWS Lambda
-Frontend: a single HTML file. No build steps, no node_modules.

It uses the zxcvbn crate to score the password, and a Mad-Libs-style generator to build the insult.

fn roast(password: &str) -> RoastResponse {
    let score  = zxcvbn(password, &[]);
    let insult = generate_insult(score.score());
    RoastResponse { score: score.score(), insult }
}

That's it. One function, one crate, one insult.

The $0.00 deployment

In the past, this is where I'd have spent days chasing a clever, scalable solution. Instead, I deployed it. The frontend is one index.html on Cloudflare Pages; the backend is a Rust binary on Lambda. It costs me $0.00/month. Is it perfect? No. Does it scale to millions? Probably not. Does it make me laugh? Yes.

Moral of the story

We're trained to think about edge cases, scalability, and "future-proofing." But for a side project, future-proofing is just procrastination with extra steps. By building something stupid, I removed the pressure to be smart — and learned more about Rust and AWS in a weekend than I would have in months of tutorials.
